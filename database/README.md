#  Database Schema

The project uses **PostgreSQL** as the primary database to store user information, device details, energy meter readings, usage summaries, notifications, and generated reports.

# Database Tables

## 1. `users`

Stores application user profile information.

Authentication is handled by **Firebase Authentication**, while PostgreSQL stores the user's profile and related data.

### Columns

| Column | Description |
|---------|-------------|
| id | Primary Key |
| firebase_uid | Firebase User ID |
| full_name | User's Full Name |
| email | Email Address |
| phone | Phone Number |
| created_at | Account Creation Time |

---

## 2. `devices`

Stores information about ESP32 smart energy meters linked to users.

Version 1 supports one device per user, but the schema is designed to support multiple devices in future releases.

### Columns

| Column | Description |
|---------|-------------|
| id | Primary Key |
| user_id | References `users.id` |
| device_id | Unique ESP32 Device ID |
| device_name | Custom Device Name |
| location | Installation Location |
| status | Online / Offline |
| created_at | Registration Time |

---

## 3. `meter_readings`

This is the core data table and the largest table in the database.

Every **30 seconds**, the ESP32 sends electrical measurements which are stored here.

### Stored Parameters

- Voltage (V)
- Current (A)
- Power (W)
- Energy (kWh)
- Frequency (Hz)
- Power Factor
- Timestamp

Because this table can grow to **millions of records**, it will be optimized using:

- Indexing
- Partitioning (future)
- Efficient queries
- Background aggregation jobs

---

## 4. `daily_usage`

Stores precomputed daily energy consumption summaries.

Instead of calculating totals from millions of raw readings each time, daily totals are stored for faster dashboard performance.

### Example

| Date | Energy Used |
|------|-------------|
| 22 Jul | 5.8 kWh |
| 23 Jul | 6.1 kWh |

---

## 5. `monthly_usage`

Stores monthly energy consumption summaries.

Used for:

- Monthly dashboards
- Electricity bill estimation
- Trend analysis
- Historical comparisons

### Example

| Month | Energy Used |
|--------|-------------|
| July | 182 kWh |
| August | 205 kWh |

---

## 6. `notifications`

Stores notifications generated by the system.

Examples include:

- High Voltage Alert
- Low Voltage Alert
- High Current Alert
- ESP32 Offline
- Daily Usage Summary
- Monthly Summary
- Threshold Exceeded
- High Energy Consumption Warning

---

## 7. `reports`

Stores metadata for generated reports.

Reports may include:

- Daily Energy Report
- Weekly Usage Report
- Monthly Consumption Report
- Electricity Bill Report
- PDF Reports
- AI Energy Analysis Reports

Typical metadata includes:

- Report Name
- Report Type
- Generated Time
- File Path / URL
- User ID
